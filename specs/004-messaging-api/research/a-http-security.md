## A1. Mounting and dispatch

**Decision.**
- `createPanelServer({ botState, admin, api, legacy, exit })` gains an optional `api` (default `admin && admin.api`) and its handler becomes `if (api && api.handle(req, res)) return; if (admin && admin.handle(req, res)) return; ...` (the rest unchanged). `lib/admin/index.js#createAdmin` builds the API object (`require("../api").createApi({...})`, no I/O, no timer) **before** `registerAll` so it is in `routeDeps` for the panel's `routes/api.js`/`services/api.js`, exposes it as `admin.api`, calls `api.start()` from `admin.start()` (after the existing hooks) and `api.stop()` from `admin.stop()`. Without an admin (`ADMIN_PANEL=false`) there is no `api`: FR-007 holds by construction, and `index.js`/`panel.js` need no change (both end in `startAdminServer({ admin })`, `lib/core/boot.js:179-180`).
- `api.handle(req, res)` returns `false` (the request falls through to `admin.handle`, then to the legacy handler) unless ALL hold: `isApiPath(req.url)` (`/^\/api\/v[0-9]+(\/|$)/` on the pathname from `splitUrl`; it does not touch `/api/info` or `/api/restart`), the API switch is on (`readSetting("API_ENABLED") === true || "true"`, read per request, capture-site rule), and the registry loaded (A3). So **disabled == never claimed == byte-identical to any unknown URL**: the legacy default branch answers `200 text/html` (status page) with the legacy CORS headers, and `OPTIONS` answers an empty `200` (`lib/admin/monitoring.js:183-192,229-232`; pinned by `test/panel-legacy.test.js:320-336`, which lists `/administrator`, `/unknown`... and must get `/api/v1/messages` and `/api/v1/openapi.json` added). No special-case code, nothing to keep in sync, no oracle on the switch.
- Boot window and restore (FR-006): when claimed, the first pipeline step is `deps.runtime && deps.runtime.dbReady !== true` or `maintenanceMode.isActive()` -> `503 unavailable`, `Retry-After: 5`, before authentication, nothing read, nothing queued. Same predicates as the panel gate (`lib/admin/index.js:185-189`, resolved lazily with `deps.maintenanceMode || require("../utils/maintenanceMode")`, `:182`). Before `settingsStore.load()` (`boot.js:201`, `dbReady` at `:209`) the switch is unknown, so during that window every `/api/v1/**` request is claimed and answered 503 whatever the switch: the answer is independent of the toggle (no leak about a disabled install, only that this build has an API, which is public). After a restore the switch is re-read from the restored settings.
- Registry failure (FR-090, US7.2): `createApi` catches the `ApiRegistryError` of A3, keeps `api.state() = { loaded: false, failure: { endpoint, reason } }`, `handle()` returns `false` (nothing served, looks disabled) and `start()` logs `getLang("api.registry_failed", endpoint)` at error level (the language manager is reloaded after `createAdmin`, `boot.js:203`, hence the log at `start()`, not at construction). The bot, the panel and the commands keep running; the panel's `GET P/` state (API-1) reports the failure so D shows a banner and C refuses the enable switch. Not a process exit: the 002 route loader aborts boot for a broken panel route (`routes/index.js:20,39,44`), but an optional feature must not take the bot down.
- `api.stop()`/switch off (FR-002): `handle()` stops claiming on the next request (setting read per call); C cancels queued messages via `settingsStore.onChange(["API_ENABLED"], ...)` (pattern `boot.js:138`).

**Rationale.** Server-level mounting keeps `admin.handle`'s documented contract ("false for any URL outside /admin", `index.js:7`) and `/administrator` behaviour intact, and gives the cheapest possible "disabled" path (one regex and one setting read). A separate `api.handle` also keeps the panel's cookie authentication and the API's key authentication in two objects that never share a table (FR-004, see A3).

**Alternatives.** (a) Claim `/api/v1` inside `admin.handle`: changes a frozen contract and couples disabled-answer to the panel router. (b) Answer disabled with a JSON 404: differs from today's HTML-200 unknown-URL answer, which is exactly the oracle FR-001 forbids. (c) Lazy `getApi()` (build on first use) to save heap: kept as the fallback if the SC-011 measurement fails (A10); eager construction costs a few KB of declarations.

**Evidence.** `lib/admin/server.js:35-43,51-60`; `lib/admin/index.js:7,84-95,99-107,129,142,179-189,228-237,241-303`; `lib/admin/monitoring.js:183-192,229-232`; `lib/core/boot.js:138,153-180,201-209,234`; `lib/core/botRuntime.js:290`; `test/panel-legacy.test.js:320-336`.

**Files.** edit `lib/admin/server.js` (4 lines), `lib/admin/index.js` (build, expose, start/stop); new `lib/api/index.js` (`createApi(deps) -> { handle, routes, state, openapi, rights, start, stop, keys, limits }`).

## A2. Request pipeline and check order

**Decision.** `lib/api/pipeline.js#dispatch(req, res, env)` never throws and always ends the response. It sets `X-Request-Id` (`newRequestId()`, `response.js:156`) and the API header profile first, then runs the steps below in this order; the first failure answers. Rows 7-9 are the only ones that count toward origin blocking (spec US1.5: missing/unknown/revoked/expired key and IP outside the list count; a plain-HTTP, browser, key-in-URL or right/policy/quota refusal does not).

| # | Step | Failure -> HTTP, code | Counts as auth failure |
|---|------|----------------------|----|
| 1 | Gate: `dbReady !== true`, or `maintenanceMode.isActive()` | 503 `unavailable` + `Retry-After: 5` | no |
| 2 | Verb: `OPTIONS` (preflight, no CORS header ever), or a verb the router does not know | 405 `method_not_allowed`; no `Allow` for `OPTIONS` (panel precedent, `router.js:327-330`) | no |
| 3 | HTTPS: `trust.isHttps(req) \|\| isLocalRequest(req)` | 403 `https_required` | no |
| 4 | Browser call: any `Origin` header or any `Sec-Fetch-Site` header (only browsers send them; a page cannot forge `Sec-Fetch-*`) | 403 `browser_not_allowed` | no |
| 5 | Key in the URL: a query parameter named `api_key`, `apikey`, `key`, `token`, `access_token`, `authorization`, or any path/query text matching the key shape (A4) | 400 `key_in_url`; the key is never parsed, hashed or logged | no |
| 6 | Origin block: `limiter.check(origin)` | 429 `origin_blocked` + `Retry-After` (also for a valid key: the origin is blocked) | no (a blocked origin is not extended, `rateLimit.js:79-85`) |
| 7 | Authenticate: `Authorization: Bearer <token>` (exactly one, shape-checked), lookup by embedded id, constant-time compare (A4) | 401 `unauthenticated` + `WWW-Authenticate: Bearer realm="owb-api"`; same code for missing, malformed, unknown id, wrong secret | yes |
| 8 | Key state, only after the secret matched: `revokedAt`, `expiresAt <= now` | 401 `key_revoked` / `key_expired` | yes |
| 9 | IP allowlist on `trust.clientAddress(req)` (A2 note) | 403 `ip_not_allowed` | yes |
| 10 | Route match (after authentication: an unauthenticated caller cannot enumerate paths) | 404 `not_found`; 405 `method_not_allowed` + `Allow` | no |
| 11 | Right: static `right` before reading a byte; a dynamic right (`messages.send.<format>`, `media.url`) as soon as the JSON body / first multipart part is parsed (step 12) | 403 `forbidden` `{ params: { right } }` | no |
| 12 | Content-Type (`application/json`, or `multipart/form-data` where declared) and body peek: JSON <= `body.limit` (default 64 KiB, max 1 MiB, `readJsonBody`), or the first multipart part `message` | 415 `unsupported_media_type`, 413 `payload_too_large`, 400 `bad_request` | no |
| 13 | Recipient policy hook `endpoint.recipient(peek) -> to` then B's `recipients.check(key, to)` | 403 `recipient_not_allowed`; a `to` that cannot be normalised: 422 `validation_failed` `{ to }` | no |
| 14 | Chat disabled (B: `banned_chats` cache) | 409 `chat_disabled` | no |
| 15 | Idempotency (A5): JSON body: fingerprint now; hit with the same fingerprint -> replay, different -> conflict, and the request ends here | 202 + `Idempotent-Replayed: true`; 409 `idempotency_conflict` | no |
| 16 | Quotas, check only (A5): global queue, key pending, day, minute | 503 `queue_full`; 429 `pending_limit_reached`, `daily_quota_exceeded`, `rate_limited` + `Retry-After` | no |
| 17 | Strict validation of the JSON: `validate(peek, schema)` then `refine` | 422 `validation_failed` `{ fields }` (dotted paths) | no |
| 18 | Media: multipart file streamed to a temp file under the format cap, or URL fetched (A6, A7); early and final sniff | 413 `media_too_large`, 422 `media_type_mismatch`, 422 `url_forbidden`, 502 `url_unreachable` | no |
| 19 | Idempotency compare for multipart (needs the file hash), then atomic quota **reserve** (re-checks 16 synchronously, released on any later failure) | 409 `idempotency_conflict`, same quota codes as 16 | no |
| 20 | Handler -> `engine.submit(...)`; `202 Accepted`, `Location: /api/v1/messages/<id>` | typed engine errors (A9) | no |

Cross-cutting rules:
- FR-032 order is preserved (key 7-9, right 11, policy 13, disabled chat 14, quotas 16, content 17-18). A replay (15) precedes the quota step so it costs nothing; the early check (16) refuses a rate-limited client before it uploads 200 MiB, and the atomic reserve (19) keeps the limits exact under concurrency (check at 16 and reserve at 19 are separated by awaits).
- Any refusal before the body is consumed adds `Connection: close` (precedent `request.js:102-107`) so unread bytes cannot desynchronise a kept-alive connection.
- Origin throttling reuses `createLimiter` unchanged: `createLimiter({ limit: 10, windowMs: 5 * 60 * 1000, blockMs: 15 * 60 * 1000, maxEntries: 10000, now })` (its options already exist, `rateLimit.js:31-36`; `fail()` returns `newlyBlocked` which triggers the alert `api_origin_blocked`). In memory only: persisting each failure would let an attacker drive database writes; a restart resets the budget (documented). `success()` is NOT called after a good request (a valid low-privilege key must not reset the counter). Origin = `trust.originKey(req)` (IPv6 grouped by /64). Behind a proxy without `PANEL_TRUST_PROXY` all callers share the proxy's origin: documented in the docs page and the panel banner (`trust.proxyHint(req)`).
- HTTPS (FR-003): `trustProxy.isHttps(req)` already honours `X-Forwarded-Proto: https` only from a trusted peer (`trustProxy.js:226-231`). **Local exception**: `isLocalRequest(req) = isLoopback(peer) && trust.proxyHint(req).length === 0 && isLoopback(trust.clientAddress(req))`. A request from an untrusted loopback proxy that adds `X-Forwarded-*` is not local; a trusted loopback proxy forwarding a public client is not local. Own interface addresses are deliberately NOT treated as local (Docker's userland proxy presents the host's `docker0` address for Internet traffic). Needs one additive method `trustProxy.clientAddress(req)` = the unmapped effective client IP (today `originKey` returns only the /64-grouped key, `trustProxy.js:80-86,212-224`); `originKey` becomes `keyOf(clientAddress(req))`.
- IP allowlist grammar (also for D's fixture `test/fixtures/api-ip-entries.json`): one entry per item, trimmed; IPv4 `a.b.c.d`, IPv4 CIDR `a.b.c.d/0-32`, IPv6 `x::y`, IPv6 CIDR `x::y/0-128`; IPv4-mapped IPv6 and zone ids are normalised with `trustProxy.unmap` (`:43`); lower-case canonical form stored; `0.0.0.0/0` and `::/0` accepted (the owner may want "any"), hosts with bits set below the mask are masked; at most 50 entries; anything else is `invalid_format`. Compiled once per key into `net.BlockList` (the class `trustProxy.js:107` already uses); empty list = no restriction. Matching uses the full client address, never the /64 key.
- Cookies: the pipeline never reads `Cookie`, never calls `deps.auth.authenticate` and never sets `Set-Cookie`; conversely `/admin/api/**` authenticates by cookie only, so an `Authorization` header there is inert. Both are pinned by tests (A10).
- Response headers (JSON API profile), via `applySecurityHeaders(res, { profile: "api" })` and `finish(res, { ..., profile: "api" })` (additive option; `finish` calls the panel set unconditionally today, `response.js:195`): `Cache-Control: no-store`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-origin`, no `Access-Control-*` (still stripped, `security.js:58-60`), no `Permissions-Policy`/COOP (not HTML), no HSTS (the proxy terminates TLS). Rate-limit headers `RateLimit-Limit/Remaining/Reset` on responses of quota-bearing endpoints (per-minute window).
- Logging: debug line `{ requestId, endpoint id, status, ms, keyId }` (keyId is the public lookup id, never the secret); auth failures at `info`, deduplicated per origin with `cooldown.hit(origin, "apiauth", 60000)` so the 1000-entry ring cannot be flooded; never `req.url`, `req.headers`, `req.body` (the 002 rule `test/admin-logging.test.js:9,182` covers `lib/admin/**` only: extend its walker to `lib/api` and `lib/messaging`).

**Rationale.** Cheap stateless refusals first, then the stateful origin check, then the secret; rights before body so an unauthorised key cannot make the server read or store anything; the replay before the quota so a lost response can be retried at the limit.

**Alternatives.** Counting right/policy refusals as failures: rejected, a valid key mis-configured would lock its whole origin. Persisting limiter state: rejected above. Refusing only `Origin` values that differ from `Host`: rejected, FR-004 says "no browser pages at all" and `Sec-Fetch-Site` alone would not catch old browsers.

**Evidence.** `lib/admin/http/router.js:315-430` (the panel dispatch order this mirrors: match, gate, auth, guard, body, handler); `lib/admin/http/security.js:40-61,157-160`; `lib/admin/http/trustProxy.js:26-245`; `lib/admin/auth/rateLimit.js:26-136`; `lib/admin/http/request.js:56-107,129-131`.

**Files.** new `lib/api/pipeline.js`, `lib/api/limits.js`, `lib/api/ipRules.js`; edit `trustProxy.js`, `security.js`, `response.js` (additive).

## A3. Endpoint declaration contract, registry, router

**Decision.** A small dedicated router (`lib/api/router.js`, about 120 lines), not a generalised `lib/admin/http/router.js`. Reused as imports: `request.js` (`splitUrl`, `parseQuery`, `readJsonBody`, `validate`), `response.js` (`newRequestId`, `errorBody`, `finish`, `reply`), `security.js` (`mediaType`, `safeEqual`), `trustProxy.js`, `rateLimit.js`. Only the path matcher (`parsePath`, literal/`:param` segments, no regex, patterns required per param, ambiguity check by shape) is re-implemented, restricted to what the API needs.

One module per endpoint, `lib/api/endpoints/<name>.js`, loaded in sorted order by `lib/api/registry.js#loadEndpoints({ dir, formats })`:

```js
module.exports = {
  id: "messages.create",                  // /^[a-z]+(\.[a-z]+)+$/, unique; OpenAPI operationId, log field
  method: "POST", path: "/api/v1/messages", params: {},   // ":id" needs params: { id: /^msg_[A-Za-z0-9_-]{22}$/ }
  right: "messages.read",                 // STATIC form: one right id, /^[a-z]+(\.[a-z0-9_]+)*$/
  // DYNAMIC form (send): rights: ({ formats }) => ["messages.send.text", ..., "media.url"] (every id the
  // endpoint can require: panel catalogue + OpenAPI) and requires: (peek) => ["messages.send.image", "media.url"]
  query:  { wait: { type: "boolean", default: false } },          // request.js dialect, strict
  body:   { kinds: ["json", "multipart"], limit: 65536,           // "none" for GET/DELETE
            schema: {...} | variants: { by: "format", schemas: ({ formats }) => ({ text: {...} }) },
            refine: (body) => fieldsOrUndefined,                    // cross-field checks (distinct options, ranges)
            file: { part: "file", maxBytes: (body) => n, accept: (body) => ({ kinds, mimes }) } },
  recipient: (peek) => peek.to,           // optional: tells the common layer which recipient to evaluate
  idempotent: true, quota: { messages: true },                     // optional
  response: { status: 202, schema: {...}, headers: ["Location"] },
  deprecated: undefined,                  // { since, sunset, link } -> OpenAPI + Deprecation/Sunset headers
  doc: { summary, description, tags: ["messages"], examples: { text: {...} } },   // English (A8)
  async handle(ctx) { return reply(202, { message }) },
};
```

`ctx = { req, res, requestId, endpoint, params, query, body (fresh validated object), file ({ path, size, mime, sha256, adopt(dest) } | null), key: Object.freeze({ id, lookupId, name }), origin, now, signal, idempotencyKey, audit }`. The handler never sees the key's hash, rights or the raw request; the temp file is deleted by the pipeline in a `finally` unless the handler called `ctx.file.adopt(dest)` (rename into the engine's pending directory).

Registry rules (each violation throws `ApiRegistryError { endpoint, file, reason }`, so the message names the endpoint): `right` or (`rights` + `requires`) present and well-formed (**deny by default, no `public` level exists**); `id` and `method path` shape unique; path under `/api/v<n>/`; every `:param` has a pattern; `GET`/`DELETE` have no body kind; `body.limit <= 1 MiB`; `multipart` needs `file`; `schema` rules valid; `doc.summary` string; `handle` function; a `requires()` result outside `rights()` is a runtime programming error (500, logged, never a grant). The registry also returns the **rights catalogue** `[{ id, group, format }]` (groups `send`, `read`, `media`, `docs`; the union of every endpoint's `rights`, which for the send endpoint comes from `formats.list()`), consumed by C (API-3), D (`api.right.<id>.label|.desc` catalog keys, D2) and the OpenAPI builder; this is why a new format or endpoint shows up in the panel with no other edit (FR-092, SC-009).

v1 endpoints (modules, so stream B/C can rely on the names): `messagesCreate` (`messages.send.<format>` + `media.url`), `messagesGet` (`messages.read`, `GET /api/v1/messages/:id`), `messagesList` (`messages.read`, paginated, filters status/format/from/to), `openapi` (`api.docs`, `GET /api/v1/openapi.json`). `api.docs` is an ordinary right (off for a new key) because FR-090 allows no endpoint without a right.

**Rationale (router).** The panel router is welded to sessions and the admin prefix: `AUTH_LEVELS = session|public|setup` (`router.js:97`), paths must start with `/admin` (`:116`), CSRF modes only make sense with a session (`:162-169`), wildcard exclusion keys on `/admin/api` (`:99,258`), and `dispatch` calls `env.auth.authenticate` then `env.security.guard` (`:371-375`). Its table feeds `test/admin-security.test.js`, which pins the exact public set (`:33-34,176`); API routes in it would break that invariant and put a key endpoint one `auth: "session"` typo from being reachable with a cookie. Two routers with two tables make FR-004 structural. Generalising would touch the most heavily tested security surface of 002 for no reuse of the parts that differ.

**Alternatives.** Parameterise `createRouter({ prefix, authLevels, authenticate })`: rejected above. A declarative JSON/OpenAPI-first spec with generated handlers: rejected, the dynamic send endpoint (rights and schema depend on `format`) does not fit and the project avoids build steps.

**Evidence.** `lib/admin/http/router.js:92-139,141-217,253-274,315-430`; `lib/admin/routes/index.js:20,29-46` (sorted-order loader, loud failure); `test/admin-security.test.js:33-34,176`.

**Files.** new `lib/api/router.js`, `lib/api/registry.js`, `lib/api/endpoints/*.js`; additive extension of `request.js#validate` for nested objects (A9 note).

**Nested validation (needed by contacts, buttons, list choices).** `validate` has no nested support: an `object` rule only checks the type and returns the caller's object (`request.js:188-190`), arrays of objects likewise (`:172-187`). Add `{ type: "object", schema }` and `items: { type: "object", schema }` that build fresh objects and report fields as dotted paths (`buttons.1.id`, `contacts.0.phones.2`, `$unknown` per level), which is exactly the path syntax D already assumes (`d-panel-ui.md` D6). Additive: no panel schema uses `schema` on an object rule.

## A4. Key format and storage

**Decision.**
- Token: `owbk_` + 16 hex (lookup id, 64 random bits) + `_` + 43 base64url characters (the secret, 32 random bytes = 256 bits) = 65 characters. Regex for scanners and for the redactor: `owbk_[0-9a-f]{16}_[A-Za-z0-9_-]{43}`. Hex id keeps the split unambiguous (base64url contains `_`). Generated with `crypto.randomBytes`; shown once by C's create/duplicate response; the SPA shows `owbk_…<last4>`.
- Stored (stream C names the columns): `lookupId` (unique index, plain), `secretHash` = hex SHA-256 of the 43-character secret **string** as sent (not of decoded bytes: base64url has non-canonical encodings of the same bytes), `last4` = last 4 characters of the token.
- Hash choice: SHA-256, not scrypt. The secret is 256 bits of uniform randomness, so a stolen database cannot be brute-forced whatever the hash speed, while a memory-hard KDF would charge every request tens of milliseconds of CPU (DoS amplification, SC-010). Same split as 002: random 32-byte cookie and one-time tokens are SHA-256 (`sessions.js:54,311`, `tokens.js:12-15,22`, `AdminSession.js:6-9`), only the human password is scrypt (`auth/password.js`).
- Verification (`lib/api/keys.js#authenticate(token)`): shape regex, then `Map.get(lookupId)` on the cached key set, then `crypto.timingSafeEqual(Buffer.from(row.secretHash, "hex"), sha256(secret))`; an unknown id compares against a dummy hash so both paths cost the same. Revoked/expired/IP are evaluated only after the secret matched, which is why `key_revoked`, `key_expired` and `ip_not_allowed` leak nothing to someone who does not hold the whole secret (A9).
- Cache: all `ApiKey` rows in `settingsCache.getOrLoad("api_keys", loader, 5 * 60 * 1000)` as `Map<lookupId, KeyRecord>` with `rights: Set`, compiled `BlockList`, `expiresAt`/`revokedAt` as ms. Every writer (C's service: create, edit, revoke, duplicate) calls `settingsCache.invalidate("api_keys")` in the same tick, so a revocation applies to the very next request (FR-014); restore and in-process restart already call `settingsCache.clear()` (`restore.js:663`, `botRuntime.js:203`). A load failure with an empty cache returns null -> `503 unavailable` (fail closed; `settingsCache.js` returns the stale value or null on error). Add `api_keys` to the key list comment (`settingsCache.js:8-11`).
- `lastUsedAt`/`lastIp`/`seenIps` are written write-behind from the request path (at most one update per key per 60 s, and at once for a new IP), no timer. A new IP (grouped like `originKey`) raises `alerts.raise("api_new_ip", { key: name, origin })` when the toggle is on (C adds the alert types `api_origin_blocked`, `api_new_ip`; payload fields only, `lib/utils/alerts.js` rebuilds payloads field by field).
- Log redaction: the redactor is value-based and the server never holds the plaintext of a presented key, so a value registration cannot cover it (`redactor.js:1-18,111-123`). Two additions: (1) a built-in pattern list in the leaf (`BUILTIN_PATTERNS = [/owbk_[0-9a-f]{16}_[A-Za-z0-9_-]{43}/g]`, applied by `scrub` after the value alternation, `redactor.js:146-153`; a regex constant adds no import, the leaf rule of `test/admin-logging.test.js:7` holds), always on whether or not the API is enabled; (2) C registers the freshly created secret with `redactor.registerEphemeral("apikey:<lookupId>", token, 10 * 60 * 1000)` for the create response. `logger.js:89`, `ring.js:87` and `audit.js:12` already pass everything through `scrub`; the pino `req.headers.authorization` path (`logger.js:33`) stays as a last line.

**Rationale.** One indexed lookup in memory, no scan (the panel scans at most two rows for tokens, `tokens.js:44-58`; keys may be dozens); scanner-friendly fixed layout; nothing secret derivable from the id.

**Alternatives.** Numeric DB id in the token: leaks creation order and count. HMAC with a server pepper: no gain over a 256-bit secret. A checksum suffix (GitHub style): rejected, a prefix plus fixed length already gives scanners a precise regex; typos cost one cached lookup.

**Files.** new `lib/api/keys.js`; edit `lib/admin/logs/redactor.js` (+ its test), `lib/utils/settingsCache.js` (comment). **Evidence** as cited.

## A5. Quotas and idempotency

**Decision (quotas).** `lib/api/limits.js#createQuotas({ now, engine, config })`, per key in memory: `minute` = sliding list of acceptance timestamps over 60 s (at most `perMinute` entries), `day` = counter for the local calendar day in `TIMEZONE` (`stats.dayOf`-style via luxon, `stats.js:74-81`), hydrated lazily once per key per process from `ApiMessage` rows accepted today (one `COUNT`, so a restart cannot reset the day), then maintained in memory. `check(key)` (step 16) is non-consuming; `reserve(key)` (step 19) re-checks and pushes synchronously and returns `{ release() }`, called on any failure before `engine.submit` succeeds. Pending counts are the engine's (B): `engine.pendingOf(keyId)` and `engine.queueSize()`, enforced again atomically inside `submit` under `withLock`.

| Limit (default) | Code, status | `retryAfterMs` |
|---|---|---|
| global queue 500 (`queueSize() >= cap`) | `queue_full` 503 `{ scope: "global" }` | `spacing * (size - cap + 1)`, clamped 1 s..300 s |
| per-key pending 100 | `pending_limit_reached` 429 `{ limit }` | `spacing * (pending - max + 1)`, same clamp |
| per-key day 1000 | `daily_quota_exceeded` 429 `{ limit }` | ms to the next local midnight |
| per-key minute 30 | `rate_limited` 429 `{ limit }` | `oldest + 60 s - now` |

The spacing (>= 2 s, +0..20 %) is the engine's; the API only reports it. Evaluation order within step 16 is the table order. `Retry-After` is `ceil(ms / 1000)` min 1, produced from `params.retryAfterMs` exactly like the panel (`response.js:123-127`).

**Decision (idempotency).** Header `Idempotency-Key: ^[A-Za-z0-9._:-]{1,80}$` (a header keeps the JSON schema clean and the multipart request identical), scoped by API key. Stored on `ApiMessage`: `idempotencyKey` (nullable) and `idempotencyFp` (nullable), unique index `(keyId, idempotencyKey)` (allowed: new table; NULLs do not collide on SQLite and Postgres). Fingerprint: `HMAC-SHA256(key = row.secretHash bytes, data = endpoint.id + "\0" + canonicalJson(rawBody) + "\0" + fileSha256-or-empty)`, hex, truncated to 32 chars; `canonicalJson` sorts keys recursively; query options such as `wait` are excluded. No content is stored: the HMAC key is per API key (no cross-install dictionary) and both columns are set to NULL once the window ended. Window: a row whose `acceptedAt` is older than 24 h no longer counts: on a hit with an expired row the request, inside `withLock`, sets the old row's two columns to NULL and inserts the new message; C's daily housekeeping nulls expired pairs so the stored fingerprint lives at most about 48 h. Same fingerprint -> `202` with the current state of the stored message and `Idempotent-Replayed: true` (no quota, no validation, no engine call); different -> `409 idempotency_conflict`. A malformed header is `422 validation_failed` `{ "idempotency-key": { code: "invalid_format" } }`. Panel test sends have no idempotency key.

**Rationale.** Memory counters are exact in a single process and need no timer; the daily count survives restarts because acceptance rows exist anyway (history). Calendar day matches the panel's per-day usage (FR-083, `DailyStat` uses the same zone); a rolling 24 h window would make the "usage per day" screen disagree with the quota. A DB-side unique index makes two racing identical requests safe (one insert wins; the loser re-reads and replays).

**Alternatives.** Rolling 24 h day (open point 4). SQL `COUNT` on every request: needless I/O on the hot path (SC-010). Separate idempotency table: another model, same semantics. Plain SHA-256 fingerprint: lets a database reader confirm guesses of short texts.

**Evidence.** `lib/admin/http/response.js:123-127`; `lib/utils/stats.js:74-81`; `lib/utils/mutex.js` (`withLock`, CLAUDE.md); `lib/utils/broadcaster.js:35,76-79` (spacing owner).

**Files.** new `lib/api/limits.js`, `lib/api/idempotency.js`.

## A6. Uploads (multipart)

**Decision.** A hand-written, restricted, streaming parser, `lib/api/multipart.js` (about 65 lines), plus `lib/api/upload.js` that owns the temp file. No new dependency.
- Grammar: `Content-Type: multipart/form-data; boundary=<1-70 RFC 2046 chars>` (quoted or not), at most 2 parts, in order `message` (JSON text, any part Content-Type or none: no-code tools send a text field, not a typed part) then `file`; each part header block <= 4 KiB, exactly `Content-Disposition: form-data; name="..."[; filename="..."]` plus an optional `Content-Type`; duplicate headers, folded lines, `Content-Transfer-Encoding` (so no base64), a third part, a missing closing boundary, a preamble over 1 KiB: all `400 bad_request`. `file` before `message`: `422 validation_failed { file: { code: "invalid_order" } }` (the right and the cap are only known after the JSON part). The `filename` of the part is a hint for the document name (sanitised by B); the JSON part may carry `fileName`.
- Streaming: the `message` part is buffered up to `body.limit` and parsed (that is the step-12 peek); after steps 11-17 pass, the `file` part is piped to `data/tmp/api/<random>.part` (mode 0600, `flags: "wx"`, same pattern as `uploads.js:227`) through a counting `Transform` capped at `min(MAX_UPLOAD MB, format.media.maxBytes)`; an overflow destroys the request and answers `413 media_too_large { maxBytes }` after at most `cap + 64 KiB` bytes. A declared `Content-Length` over `64 KiB + cap + 16 KiB` is refused before reading anything. SHA-256 is computed on the fly (idempotency).
- Sniffing: `file-type` v22 (already a dependency, ESM, `await import`), never the declared type. Early sniff on the first 4,100 bytes (`reasonableDetectionSizeInBytes`, `file-type/source/index.js:27`) aborts a wrong type after one chunk (`media_type_mismatch`, file deleted); a final `fileTypeFromFile` confirms containers that need more bytes. The accepted kinds/mimes per format come from B's `format.media`. Reuse of `lib/admin/http/uploads.js` stays on the panel side: it is session-keyed and one-in-flight, its `PURPOSES` is `["backup","broadcast"]` and its sniffer admits only images/documents (`uploads.js:47,94-127`); C adds purpose `api` there for the panel test form only.
- Limits: in flight at most 2 per key and 4 globally (`429 rate_limited { scope: "uploads" }`), a per-chunk idle timeout of 30 s, total pending media bytes (`engine.pendingMediaBytes()` + in flight) <= `2 * MAX_UPLOAD` else `503 queue_full { scope: "disk" }` (the panel uses the same 2x rule, `uploads.js:208`). Node's `server.requestTimeout` (5 min default) bounds a slow upload; `Expect: 100-continue` is auto-acknowledged by Node (a `checkContinue` gate is an optional hardening, not needed).
- Cleanup on every path: `try/finally` in `upload.js` unlinks the `.part` on any error, abort (`res.on("close")` -> `AbortSignal`), mismatch or cap; success hands the file to the handler as `ctx.file`, whose `adopt(dest)` renames it into the engine's pending directory (B/C own the orphan sweep, FR-075).

**Rationale.** The grammar is two parts, so the parser is tiny, and a strict subset removes the smuggling/quirk surface of general parsers. Spike: 2,800 random chunk splits (including 1-byte chunks and bodies containing `\r\n--`, a prefix of the boundary, and boundary-like text) reproduced both parts exactly; the five malformed bodies (truncated, third part, transfer encoding, oversize header, garbage) were rejected; 200 MiB parsed in 38 ms with a 64 KiB chunk size (heap flat, the file bytes never accumulate). The repo hand-writes its HTTP layer on purpose (no express, own router, own uploads) and checks unused dependencies in CI (`tools/check-unused-deps.js`).

**Alternatives.** `busboy` (or `@fastify/busboy`, zero deps): solid and fuzzed, but not in the tree (`yarn.lock` has no busboy/formidable/multer), one more dependency to audit for an input class we can restrict to two parts, and we would still write the same ~80-line wrapper for caps, ordering, hashing and cleanup. Node's `Request.formData()`: buffers the whole body, no cap. Raw octet-stream upload with parameters in the query (the panel's pattern): puts recipients in proxy logs and has no JSON part. Fallback if the parser's test battery ever shows a gap: switch the one file to `@fastify/busboy` behind the same `parseMultipart(source, boundary, onPart)` signature.

**Files.** new `lib/api/multipart.js` (+ `test/api-multipart.test.js` with the random-split fuzz, boundary-straddling and malformed cases), `lib/api/upload.js`. **Evidence** `lib/admin/http/uploads.js:47,94-127,162-167,188-266`; `lib/admin/http/request.js:56-107`.

## A7. SSRF-safe URL fetcher (`lib/messaging/urlFetch.js`)

**Decision.** `createUrlFetcher({ resolve, request, now, maxBytes, deadlineMs, tmpDir })` with `fetchMedia(urlString, { maxBytes, signal }) -> { path, size, contentType, sha256 }` (streamed to a temp file) and the pure helpers `validateUrl(text) -> URL`, `isPublicAddress(ip)`. Algorithm, per hop (at most 4 hops = the first request plus 3 redirects):
1. `validateUrl`: `new URL(text)` (this is the only parser; the connection always uses the parsed object, so `user@host`, backslash and numeric-host tricks cannot diverge); protocol exactly `https:`; empty `username`/`password`; `port === ""` or `"443"` (the parser drops a default port); hostname, after stripping one trailing dot, is not an IP literal at all (forbidden outright, which also removes decimal/octal/hex/short IPv4 forms: the parser rewrites `2130706433`, `0x7f.1`, `127.1` to `127.0.0.1`), not `localhost`/`*.localhost`/`*.local`/`*.internal`/`*.localdomain`, and has at least one dot; length <= 253. Violation: `url_forbidden`.
2. Resolve once per hop: `dns.promises.lookup(host, { all: true, verbatim: true })`, inside the global deadline. **Every** returned address must pass `isPublicAddress`, otherwise `url_forbidden` (a name with one public and one private record is refused whole, which defeats round-robin rebinding). No address / `ENOTFOUND` / `EAI_AGAIN`: also `url_forbidden { reason: "host" }` (not `url_unreachable`, to avoid an oracle that tells internal names that exist from names that do not; connection failures to a public address are the `url_unreachable` case).
3. Connect to the validated address itself: `https.request({ host: <ip>, servername: <hostname>, headers: { Host: <hostname> }, agent: false, maxHeaderSize: 16 KiB, rejectUnauthorized: true })`. The socket goes to exactly the IP that was checked (no second resolution, so no TOCTOU, and no reliance on a `lookup` callback that IP-literal hosts would skip); TLS verifies the certificate against the hostname through `servername`. Spike: the real `https` module with a self-signed certificate accepted the matching name and failed `ERR_TLS_CERT_ALTNAME_INVALID` for a different one while connecting to `127.0.0.1`. `agent: false` = a fresh agent per request, no pooling, and no environment proxy. Spike on Node 24.20 with `NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:1`: the default global agent went to the proxy (`ECONNREFUSED`), `agent: false` and `new https.Agent()` connected directly. A proxy would resolve names itself and bypass step 2, so a test pins `agent: false`.
4. Request: `GET`, headers `Host`, `User-Agent: OpenWhatsappBot`, `Accept: */*`, `Accept-Encoding: identity`; no `Cookie`, no `Authorization`, nothing forwarded from the caller; `Set-Cookie` ignored. Response: `200` only; `301/302/303/307/308` with `Location` resolved against the current URL and sent back through step 1 (a redirect to `http:`, a port, credentials or an internal name is `url_forbidden`; more than 3 redirects is `url_forbidden { reason: "redirects" }`); any other status or `Content-Encoding` other than identity: `url_unreachable`.
5. Body: counted while streaming into the temp file whatever `Content-Length` says (a declared length over the cap only short-circuits), cap `min(MAX_UPLOAD MB, format.media.maxBytes)` -> `media_too_large`; the first 4,100 bytes go through the early `file-type` sniff (A6) and a mismatch aborts the download. One `AbortSignal.timeout(30000)` covers DNS, all hops and the body (a server that drips one byte every 5 s is cut at 30 s); timeouts, resets, TLS errors: `url_unreachable`.
6. Cleanup: the temp file is deleted on every error path; success returns it to the same hand-off as an upload (A6).

`isPublicAddress` uses `net.BlockList` (as `trustProxy.js:107` does) with IPv4: `0.0.0.0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24, 192.0.2/24, 192.88.99/24, 192.168/16, 198.18/15, 198.51.100/24, 203.0.113/24, 224/4, 240/4`; IPv6: `::/128, ::1/128, ::/96` (IPv4-compatible), `64:ff9b::/96`, `64:ff9b:1::/48` (NAT64), `100::/64`, `2001::/32` (Teredo), `2001:db8::/32`, `2002::/16` (6to4), `fc00::/7`, `fe80::/10`, `fec0::/10`, `ff00::/8`. **Do not add `::ffff:0:0/96`**: `BlockList.check` already tests an IPv4-mapped address against the IPv4 rules, and adding the mapped prefix blocks every IPv4 address (found by the spike). Spike result on Node 22.20 and 24.20: 0 errors on 49 cases (blocked: loopback, RFC 1918, `169.254.169.254`, CGNAT edges, multicast, `255.255.255.255`, `::1`, ULA, link-local, `::ffff:7f00:1`, `::ffff:a9fe:a9fe`, `::127.0.0.1`, `64:ff9b::a00:1`, `64:ff9b::169.254.169.254`, `2002:7f00:1::`, Teredo; allowed: `8.8.8.8`, `172.15.255.255`, `172.32.0.1`, `100.63.255.255`, `100.128.0.1`, `2606:4700:4700::1111`, `::ffff:8.8.8.8`). The list is data, frozen, with the spike's cases promoted to the unit test.

**Link preview (FR-043).** Baileys auto-generates previews itself: `generateWAMessageContent` calls `generateLinkPreviewIfRequired` whenever `message.linkPreview` is `undefined` (`baileys/lib/Utils/messages.js:278-280`), which does `import('link-preview-js')` and fetches the URL with that library's own follow-redirect logic (`baileys/lib/Utils/link-preview.js:24-37`, wired at `Socket/messages-send.js:1071-1078`). `link-preview-js` is an optional peer dependency (`baileys/package.json:92,131`), absent from `node_modules` and `yarn.lock` resolutions of this repo, so today the import fails and no fetch happens; installing it (the library Baileys recommends) would silently turn every text containing a URL, including attacker-chosen API text, into an unguarded server-side fetch. Decision: the API's text format MUST always pass `linkPreview: null` (a non-`undefined` value skips generation, `messages.js:279`), unconditionally and covered by a test that sends a URL-bearing text through a fake socket and asserts `linkPreview === null`. When `linkPreview: true` is requested (needs right `media.url`), the format builds the preview object itself through this fetcher: `fetchMedia` with `Accept: text/html`, a 256 KiB cap, the `<title>`, `og:title` and `og:description` read with two regexes and decoded with `html-entities` (already a dependency), result `{ "matched-text", title, description }` and no thumbnail in v1 (a thumbnail would need a second guarded fetch plus `sharp`; add later with the same fetcher). A fetch failure sends the text without preview and does not fail the message. Do not add `link-preview-js`.

**Rationale.** Pinning the connection to the validated IP is simpler to reason about and to test than a `lookup` hook, and it still satisfies "checked at connect time": the address connected to is the address checked, per hop. Existing `fetchBuffer` is unusable: axios buffers the body in memory, follows up to 5 redirects with no address check and caps only by `maxContentLength` (`lib/utils/http.js:136-157`).

**Alternatives.** `https.request({ lookup })` with a validating callback: equivalent for names, skipped for IP literals (we forbid those anyway), harder to inject in tests. `undici` Agent `connect` hook: `undici` is only a transitive dependency (`yarn.lock:3301`). Stripping private records and keeping the public ones: rejected, mixed answers are an attack signature.

**Tests with no network.** `resolve` and `request` are injected; the default `request` is `https.request`. The SC-007 battery (A10) asserts a spy on `request` is never called with a non-public `host`. A second group wires `request` to a local plain `http` server (`http.request({ host: "127.0.0.1", port })` ignoring the pinned address) to exercise streaming, the byte cap with a lying `Content-Length`, chunked infinite bodies, drip-feed timeouts and redirects, while the address policy still runs on the injected resolver.

**Files.** new `lib/messaging/urlFetch.js` (+ `test/url-fetch.test.js`). **Evidence** `lib/admin/http/trustProxy.js:107`; `lib/utils/http.js:136-157`; baileys paths above; `file-type/source/index.js:27`.

## A8. OpenAPI generation (FR-084, FR-005, FR-092)

**Decision.** `lib/api/openapi.js#buildOpenApi({ endpoints, formats, info, serverUrl, errors })` is a pure function returning an OpenAPI 3.1.0 object (JSON Schema 2020-12 dialect), memoised after the first build (declarations are static after boot; only `servers` varies per call). Served at `GET /api/v1/openapi.json` (right `api.docs`, `Cache-Control: no-store`) and exposed as `api.openapi({ baseUrl })` for C's panel download route (which works with the API disabled, per D). Content: `info.version = API_VERSION` (`lib/api/version.js`, semver); `servers[0].url = (PANEL_PUBLIC_URL || request-derived origin) + "/api/v1"` (relative `/api/v1` when unknown); `components.securitySchemes.bearerAuth = { type: "http", scheme: "bearer", bearerFormat: "owbk_<id>_<secret>" }` applied globally; one operation per endpoint (`operationId = endpoint.id`, parameters from `params`/`query`/`Idempotency-Key`, `requestBody` with `application/json` and, where declared, `multipart/form-data` with an `encoding` for the `message` part, response `202` plus shared error responses by `$ref`); the send operation uses `oneOf` over the format schemas with a `discriminator` on `format` and one named example per format taken from the descriptor `example`; extensions `x-required-rights`, `x-quota`, `x-idempotent`; `components.schemas.Error` with `code` as an enum of the catalogue (A9), `Message`, `MessageStatus` (the nine statuses), `FailureCode`.

Mapping (a single mapper, from the `request.js` dialect, which B's `compileFields(descriptor.fields)` also feeds for validation, so validation, docs and the test form cannot drift): `string` -> `type: string` + `minLength`/`maxLength` (JSON Schema counts code points like `codePoints`, `request.js:137`) + `pattern: rule.pattern.source` + `enum`; `int` -> `integer`; `number`; `boolean`; `array` -> `items`, `minItems`/`maxItems`; nested `schema` -> `object` with `properties`/`required`; `nullable` -> `type: [T, "null"]`; every object `additionalProperties: false` (the validator rejects unknown fields). Descriptions are English strings inside the module (`doc`), not translation keys (open point 2). 

**Versioning rules** (`docs` page and `version.js` comment): path-versioned (`/api/v1`); compatible, same major, no new path: new endpoint, new format, new optional request field, new response field, new error code, new right (denied to every existing key by default, FR-011), new enum value in a response; breaking, requires `/api/v2` served beside v1: removing/renaming a field, tightening validation of an existing field, changing a type, default or meaning, changing the code or status of an existing refusal, removing an endpoint/format. The mount already claims `/api/v[0-9]+/**` (A1), so v2 adds a second endpoint directory and a second registry, nothing else; a deprecated v1 endpoint declares `deprecated: { since, sunset, link }` -> OpenAPI `deprecated: true` and `Deprecation`/`Sunset` headers.

**Tests.** A structural checker in the test (no validator dependency exists in the tree): every `$ref` resolves, `operationId`s unique, every `{param}` of a path is declared, every operation has `security` and `x-required-rights`, every error code in responses is in the catalogue, every format has an example, and the document is byte-stable for the same declarations. The SC-009 demo test adds an endpoint file and a format and asserts all three outputs change.

**Alternatives.** Hand-maintained `openapi.json`: drifts. Swagger UI served by the bot: a browser page calling the API is exactly what FR-004 forbids and needs a relaxed CSP. **Files.** new `lib/api/openapi.js`, `lib/api/version.js`.

## Open points for the owner

1. **Clear-text calls from private networks (FR-003).** The spec exempts only "the machine itself"; I implemented loopback only. A very common layout is n8n and the bot in one `docker compose` network calling `http://bot:3000/api/v1/...` from a private address, which is refused. Recommended: keep v1 strict (terminate TLS at a proxy and set `PANEL_TRUST_PROXY`, documented on the API page), and add later, if wanted, an explicit setting `API_PLAIN_HTTP_FROM` (CIDR list, empty by default, step-up to change).
2. **Language of the OpenAPI document (FR-085).** Recommended: English only (developer-facing artifact, generators expect it); right labels, format labels and all panel/bot texts stay fr+en. If French docs are wanted, add `doc.fr` strings per module and a `?lang=` parameter later.
3. **Who may read the documentation endpoint.** Recommended: a dedicated right `api.docs`, off for new keys (every endpoint needs a right, FR-090); the owner downloads the document from the panel anyway.
4. **Meaning of "1 000 par jour" (FR-036).** Recommended: calendar day in the bot's `TIMEZONE` (same zone as the per-day usage screen, `Retry-After` = time to midnight); the alternative is a rolling 24 hours (smoother, but the usage page and the quota would disagree).
